SECTION 3 — Architecture contract
================================================================================

  React UI  ──/api/JSON──►  Django + DRF  ──ORM──►  PostgreSQL (prod) / SQLite (dev)
     │                          │
     │                          │ post_save signals + service-layer writes
     │                          ▼
     │                   audit.AuditEvent  ← Master Event Ledger
     │                          ▲
     │                          │
     │                   Provider webhooks (HMAC-verified, idempotent)
     │
     └── mock fallback ── frontend/src/services/mockData.ts (dev only since Phase 13A)

Rules:
  - Frontend → backend flows through frontend/src/services/api.ts.
  - Backend → frontend uses camelCase JSON keys (Django serializers map
    snake_case columns via source=).
  - Pages consume api only. Never import mockData.ts from a page.
  - No {success, data} envelope — endpoints return raw arrays/objects
    matching frontend/src/types/domain.ts.
  - Workflow logic lives in apps/<app>/services.py (services), not views.
    Views are parse → call service → respond.
  - Gateway integrations live in apps/<app>/integrations/ with a
    mock/test/live mode dispatch.

SECTION 24 — Operational guard rails (do not bypass)
================================================================================

Before any provider-touching CLI:
  1. Confirm the runtime kill switch is enabled.
  2. Confirm the relevant env flag is set via runtime prefix (NEVER edit
     .env.production).
  3. Confirm the Director sign-off body literally contains the required
     id references (gate id, attempt id, target order id, target payment
     id, etc.) AND BEGIN_UTC= / END_UTC= structured markers.
  4. Confirm `now` is inside the signed UTC window (15-min cap for most
     execute commands; 30-min cap for Phase 12A campaigns; 24h cap for
     Phase 7E approval-only state transitions).
  5. Confirm the operator name is non-empty.
  6. Confirm the right --confirm-... CLI flag is present.

Refusal patterns (each command writes a blocked audit row instead of
mutating state):
  - Missing structured UTC window
  - Window > permitted length
  - Window stale > 24h
  - END_UTC <= BEGIN_UTC
  - now < window start OR now > window end
  - Kill switch off
  - Env flag off
  - --confirm-... missing
  - Operator name blank
  - Idempotency lock — prior execute on same gate

Rollback is a first-class concern:
  - Phase 7E-Live-B sends are NOT rollback-able (cannot un-send WhatsApp).
  - Phase 7G test/mock AWBs are rollback-record-only (Delhivery cancel may
    refuse for in-transit shipments).
  - Phase 7D / Phase 8C / Phase 8F mutations have first-class rollback
    commands that restore the pre-execute snapshot.
  - Phase 12A Vapi calls are NOT rollback-able (cannot un-make a call).
